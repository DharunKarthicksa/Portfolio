The problem

Teams describe the same business in different words. A "customer" in the BI model, the CRM and the AI agent are three different things, so numbers disagree and every new data source takes weeks of manual mapping.

What iWeave does

It starts from a curated industry template (FIBO, GS1, ISA-95, HL7 FHIR and others), lets people reshape it in plain English, binds each entity to real tables and columns, and deploys it to Microsoft Fabric, Neo4j and other graph platforms.

My role

Software engineer on the platform. I worked on live data binding to Microsoft Fabric, the serverless API and its security, and production debugging across the stack.

iWeave

Every ontology starts from an industry template grounded in a published standard. The product ships 40+; this demo includes three.

Describe a change in plain English. The assistant turns it into structured actions that update the model through one state layer, so every change can be undone.

Try add domain …, add entity … to …, add field to Entity, link A to B as label, remove field from Entity.

Ontology structure

Each entity is bound to a physical lakehouse table. Attributes are auto-mapped to columns with a confidence score; anything uncertain is flagged for review, and you can change any mapping. The output is the binding definition Microsoft Fabric expects.
